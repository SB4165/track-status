# 트랙 진행현황

공장 배치도 기반 트랙 프로젝트 공정 진행현황 보드 (GitHub Pages + Google Apps Script + Google Sheets)

## 화면
- 진행현황 탭: 도면 형태 배치도. 배치 번호가 지정된 프로젝트만 해당 장비 위치에 표시
- 프로젝트 관리 탭: 프로젝트 등록(개수 제한 없음), 배치 번호 지정/변경, 진행중·미배치·출하완료 필터, 엑셀 다운로드
- 프로젝트 동기화 탭: 참조 시트(M열 TRACK) 목록을 대기/동기화 완료/제외로 표시하고 조건부·일괄·선택 동기화

## 구성
| 파일 | 역할 |
|---|---|
| index.html, style.css, app.js | 화면 (PC/모바일 반응형) |
| config.js | Apps Script 웹앱 URL 설정 (비워두면 데모 모드) |
| Code.gs | 백엔드 API (Apps Script에 붙여넣기) |

## 데이터 (DB 스프레드시트: "트랙 업무 진행현황 DB")
- Layout: 배치도 요소 (id, type, slot, label, x, y, w, h, active)
- Projects: 프로젝트 (slot 비어 있으면 미배치, state: active / shipped / removed)
- Steps: 프로젝트별 17개 공정 현재값 (11. 로봇 배선 해체(제조), 12. 클리닝(제조), 17. 출하완료 포함. 공정 목록 변경 시 STEPS_VERSION으로 기존 데이터 자동 이전 + 백업 시트 생성)
- History: 모든 변경 이력 (저장 시점의 공정 전체 내용 스냅샷)
- SyncState: 동기화 제외 목록 (name, state=excluded)

프로젝트명은 참조 시트(BACKLOG STATUS › SYSTEM)의 **TYPE 열에 TRACK이 포함된 행의 PROJECT NO.** 값을 사용합니다. 열은 1행 헤더 이름(PROJECT NO. / TYPE / Factory Out Date)으로 찾으므로 열 위치가 바뀌어도 자동 추적됩니다 (헤더 이름이 바뀌면 Code.gs의 REF_HEAD 수정).

## 배치 변경 (사옥 이전)
Layout 시트는 가로 1000 좌표의 도면입니다 (세로는 가장 아래 요소에 맞춰 자동).
- type = slot: 장비 위치 (slot 열에 배치 번호)
- type = pack: 패킹 칸 (slot 9, 10 …). 현재 공정이 12번(클리닝(제조)) 이상인 프로젝트만 배치 가능
- type = wall: 벽면 프레임 막대
- type = fixture: 테이블 같은 고정물 (label에 이름)
- type = door: 출입문 표시
- type = label: 글자만 표시
- type = note: 기타사항 메모 칸 (누르면 입력, 내용은 Notes 시트에 저장). 행을 추가하면 메모 칸을 여러 개 둘 수 있음
x, y(왼쪽 위 좌표)와 w, h(크기)를 바꾸면 화면이 그대로 다시 그려집니다. 행 추가로 칸/고정물 추가, active를 FALSE로 바꾸면 숨김.
프로젝트 기록은 프로젝트 ID에 저장되므로 배치가 바뀌어도 유지됩니다.

## 진행·이슈 요약 자동 초안
요약을 직접 쓰지 않으면 공정 기록으로 자동 초안을 만들어 카드와 상세 창에 채웁니다. 진행사항 = 현재 공정의 세부 진행사항, 이슈사항 = 미완료 공정의 이슈(내용 없는 조치중·보류는 공정명)를 요약해서 표시합니다. 요약 규칙: 번호/줄 단위로 항목을 나누고 숫자 없는 괄호 메모를 지운 뒤 항목마다 한 줄씩(여러 개면 1. 2. 번호, 문장은 자르지 않음). 카드에서는 번호 항목마다 줄바꿈하고 진행·이슈 각각 최대 6줄(카드 공간만큼), 카드가 꽉 차면 긴 쪽부터 줄을 줄이며 '…' 표시. 전체 내용은 요약에 마우스를 올리거나 카드를 눌러 상세 창에서 확인. 고쳐 저장하면 '직접 작성'으로 고정되고, '자동 초안으로' 버튼으로 되돌릴 수 있습니다.

## 프로젝트 그룹 필터
프로젝트 관리 탭의 그룹 선택으로 세트별 보기. 규칙: 'MISC-XXXX #1' → 'MISC-#1', 'RD-SH-13-013 XXX#1' → 'RD-SH-13-013'.

## 특정 공정부터 진행
- 등록 시 '시작 공정'을 고르면 이전 공정은 '완료'로 등록됩니다 (작업은 이미 끝났고 기록만 입력하지 않은 것).
- 이미 등록된 프로젝트는 상세 창의 '시작 공정 → 이 공정부터 진행'으로 이전 미완료 공정을 한 번에 '완료' 처리 (기존 완료 기록 유지).
- '생략' 상태는 '입력 생략' 의미로 개별 공정에 직접 지정할 수 있으며, 현재 공정 계산·진척률에서 완료와 같이 취급됩니다.

## 프로젝트 동기화
- 참조 시트 PROJECT NO.·TYPE·Factory Out Date(출하일, 공란은 '미정') 열을 헤더 이름으로 읽어 TYPE에 TRACK이 포함된 행만 표시. No.는 시트 등록 순서 (10분 캐시, 새로고침 버튼은 즉시 재조회)
- 상태: 대기(미등록) / 동기화 완료(같은 이름의 진행중·출하완료 프로젝트 존재) / 제외(SyncState)
- 조건부 동기화 = 현재 필터의 대기 건 전체, 일괄 동기화 = 모든 대기 건, 선택 동기화 = 체크한 대기 건. 행마다 시작 공정·배치 지정 가능 (사용중이거나 조건이 안 맞는 배치는 미배치로 등록)
- 동기화 취소 = 프로젝트 관리 탭에서 삭제(state=removed), 선택 제외 / 제외 해제 지원, 이력 보기에서 동기화 관련 변경 확인

## 패킹 칸 드래그
배치도에서 배치된 카드를 패킹 칸(1~8)으로 끌어 놓으면 '패킹존으로 이동하시겠습니까?' 확인 후 이동합니다 (12번 공정 이상만, 사용 중인 칸이면 기존 프로젝트 미배치 확인).

## 프로젝트 수정·삭제
프로젝트 관리 탭 각 행의 연필(프로젝트명 수정) / 휴지통(삭제) 아이콘, 또는 상세 창 하단 버튼. 모든 변경은 History에 기록.

## 저장 속도
저장은 화면에 즉시 반영되고 서버 동기화는 백그라운드에서 순서대로 처리됩니다 (상단에 '저장 중…' 표시).

## 엑셀 다운로드
프로젝트 관리 탭 > 엑셀 다운로드: 프로젝트 현황 / 공정별 현재값 / 변경 이력 3개 시트. 프로젝트와 이력 기간으로 필터 가능.

## 입력·수정·삭제 비밀번호
Apps Script > 프로젝트 설정 > 스크립트 속성에 WRITE_KEY(값 = 비밀번호)를 추가하면 저장·수정·삭제 시 비밀번호를 묻습니다.
같은 창(탭)이 열려 있는 동안은 한 번만 입력하면 되고, 탭을 닫으면 다시 묻습니다. 비밀번호는 코드(공개 저장소)에 넣지 않습니다.

## 코드 수정 후 배포
1. Code.gs 수정 후 저장, setup 실행 (시트 구조 자동 정리. 기본 배치를 다시 깔려면 Code.gs의 LAYOUT_VERSION 값을 올림)
2. 배포 > 배포 관리 > 연필 아이콘 > 버전: 새 버전 > 배포 (웹앱 주소 유지)

## 추후 자동화
4)~10), 14), 15) 공정의 NAS 파일 업로드 확인은 Steps.fileCount, Steps.fileCheckedAt 열에 사내 PC 스크립트가 결과를 기록하는 방식으로 연동 예정입니다.
